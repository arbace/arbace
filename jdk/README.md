# jdk/

The JDK's part of the Go build's input (standalone stage S1, [doc/STANDALONE-SURVEY.md](../doc/STANDALONE-SURVEY.md)
§4.2, D2; [doc/go/JRT-SOURCES.md](../doc/go/JRT-SOURCES.md), "The committed forms"): the class
forms of the JDK classes jrt translates, as repr/java converts them, and the resource data the
executables embed. These are the sources the Go build reads: `bin/a2g` (so `bin/arbace-go
--build`, `--build-tests`, `--build --box` and the gate's cached executable) takes its JDK input
from `jdk/forms` and the data beside it, `jdk/data`, without javac, the JDK's build tools or
jdk26u's checkout. They are generated, not edited: `bin/jrt-convert update` writes them,
`bin/jrt-convert verify` (run by `bin/gate --full`) converts afresh and compares, byte for byte.

| path | what | from |
|---|---|---|
| `forms/` | one class forms file (`.ae`) per Java source of the closure, at its package path, as repr/java writes it (`bin/repr-java read-jdk --check`, attributed as `java.base`; repr/java on the frozen JVM Arbace since S4, `bin/lib/frozen.bash`); the first line names the source (`;; Converted from ...`) | jdk26u's Java sources; the sources jdk26u's build generates (`CharacterData*`, java.nio's buffers, `ScopedMemoryAccess`, the CLDR locale data, `LocaleEquivalentMaps`), generated by `bin/jrt-convert` with the build's own tools; `jdk/internal/jrt/LocaleDataIndex` (generated by `test/jrt/jrt_sources.ae`); jrt's own Java, `overlay/jdk/java.base` |
| `data/` | the resource data under their resource paths: `java/lang/uniName.dat`, `java/util/currency.data`, ICU's `nfc.nrm`, `nfkc.nrm`, `ubidi.icu`, the break iterators' data, `lib/tzdb.dat`, `conf/security/java.security` | made by `bin/jrt-convert` as jdk26u's build makes them (doc/go/JRT-NOTES.md, "The JDK's resource data") |
| `sources.txt` | the closure's files, one per line: module, kind (`share`, `share:MODULE`, `unix`, `gensrc`, `gensrc:MODULE`, `jrtgen`, `overlay`), path; and the locales line | `test/jrt/jrt_sources.ae` (`print-sources`, over `doc/go/java-surface.edn`) |
| `edge.edn` | a2g's edge: the classes outside the forms as a2g sees them on the JVM (class infos in `arbace.classes.env`'s shape and the analyzer's other facets, the cut classes' public members, the JVM's overload order of archived classes, ...), so that a2g runs without the JVM's reflection or ASM ([doc/STANDALONE-NOTES.md](../doc/STANDALONE-NOTES.md), S2) | recorded by `bin/a2g-edge update` (a2g's `--record-edge` on the JDK 26 build of jdk26u and, since S4, the frozen JVM Arbace, `arbace-for-java-26-v4`'s jar with a2g and the class forms' front end from the checkout; until S4 Arbace's `target/stage2`); `bin/a2g-edge verify` (run by `bin/gate --full`) records afresh and compares |
| `provenance.edn` | jdk26u's repository, commit and whether its checkout was clean; the JDK whose javac attributes the sources; the JDK that ran the generators; the locales (`JRT_LOCALES`); the converter's version (a hash of `arbace/repr/java{.ae,/}` and `bin/repr-java`) and its host since S4 (the frozen jar's name and SHA-256); the counts | `bin/jrt-convert` |

Origin: https://github.com/openjdk/jdk26u at `baf63fbe42b8758448fee570a9d9bb914272d259`
(2026-08-18), the local checkout `/root/jdk26u` (`JDK`), with the JDK built from it (26.0.2.1)
running repr/java and the boot JDK 25.0.4 running the generators; converted on 2026-10-12 by repr/java as of
Arbace's main at `61dc18b` (the commit that first added this tree records the rest), with the
default locale set (`JRT_LOCALES` none: java.base's root and English data).

When to regenerate (`bin/jrt-convert update`, then commit `jdk/` with the change): after a change
to what the conversion reads: jrt's own Java (`overlay/jdk/java.base`; not `overlay/jdk/variants`,
which a2g reads directly), the closure (`test/jrt/jrt_sources.ae`, `doc/go/java-surface.edn`),
repr/java (`arbace/repr/java{.ae,/}`, which `provenance.edn`'s hash names), jdk26u's checkout or `JRT_LOCALES`.
`verify` fails until then. `JRT_CONV=DIR` points `bin/a2g` at another conversion (its data in
`DIR/../data`), for instance `.tmp/jrt/conv`, the last run's. `edge.edn` is regenerated by
`bin/a2g-edge update` after a change to what a2g asks of the JVM: references outside the world
(in `arbace/lang`, the JDK's forms, the embedded namespaces), a2g or the class forms' analysis;
`bin/a2g-edge verify` fails until then.
