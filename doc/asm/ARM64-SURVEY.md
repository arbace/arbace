# AArch64 (arm64) assembly language as a crop: survey and plan

Status: survey and plan, 2026-11-09, at the user's request: AArch64 assembly language as a crop of its own, its row of the
REAP matrix (read, eval, AOT, print) and its judge, modelled on LLVM IR's (doc/llvm/LLVM-CROP-SURVEY.md: its stages, its own
verdicts, its packs and its independence rules). A sibling survey for amd64 is written at the same time
(doc/asm/AMD64-SURVEY.md, branch `asm-amd64-survey`); §11 proposes what the two share, so that they can be merged into one
plan. Nothing here is adopted: only this file and a journal entry were written; no code under `arbace/`, `go/`, `bin/`,
`tools/` or `test/` changed. The decisions are the user's, as ARS1-ARS16 (§13) and the shared ones SH1-SH10 (§11); the
milestones are AR0-AR12 (§12).

Base: branch `asm-arm64-survey` from `mac/next` `7da5badcf`. The work is reading (the LLVM survey, doc/CROPS-SCORE.md,
`test/crops/crops.edn`, `test/reap/cells.edn`, doc/ORACLE-RECORDS-SURVEY.md, doc/go/BOX-NOTES.md's S4, `bin/box-arm64-vm`,
`tamago/cmd/`'s `cmd/asm` and `cmd/internal/obj/arm64`, TamaGo's go tree, `go/arbace/crt/`) and light probes of seconds each
(§3) with the host's LLVM 23.1.5 tools, TamaGo's go and qemu-aarch64. Scratch in the worktree's `.tmp/asm/` (the four
llvm/test directories and gcc's `gcc.target/aarch64` extracted from the main checkout's tarballs, 32 MB). No Arbace
executable was built, no lock taken, nothing installed, nothing downloaded. What the host does not hold is named with
**to verify** and listed in §5.3 as fetches for the user's go-ahead.

Words used throughout:

- **A64**: the AArch64 instruction set (the Arm ARM's name), base, Advanced SIMD (NEON), FP, and the extensions (LSE, PAuth,
  BTI, MTE, SVE, SVE2, SME ...).
- **Assembly forms** (A64 forms here): assembly text as Arbace forms: the file's statements (labels, directives,
  instructions, comments in mode `:full`) in order; an instruction is its mnemonic and typed operands.
- **repr/asm**: the bridge between assembly text and assembly forms (`bin/repr-asm read|print|roundtrip --arch arm64
  --syntax gnu|apple|plan9`), as repr/llvm is LLVM IR's.
- **The assembler**: assembly forms → machine code → an ELF object, and the static linker of its own → an ELF executable
  (`arbace.asm.*`; the AOT stage).
- **The decoder**: machine code → assembly forms (the disassembler); the emulator's front and a judge of the encoder.
- **a64i** (name proposed, ARS14): the emulator of A64 at user level, Linux's system calls over Arbace's runtime, as ci's
  crt serves C (the eval stage).
- **The three oracles' places**: this host (amd64: LLVM's tools for A64, qemu-aarch64, no arm64 hardware); the emulated
  aarch64 VM (`bin/box-arm64-vm`: QEMU's system emulation, KVM/arm64 inside it); the **Mac VM** (Alpine edge aarch64 on
  the user's M2 Max, real arm64 cores; the queue repo `mac`); and macOS itself (Hypervisor.framework's host, Apple's
  toolchain, Mach-O).

## 1. What parity means

The crops' rule for a language without a front end to stand in for: the subject is the assembly text itself, any
producer's; the reference is the assembler's and the machine's reading of it, here stated by the tests themselves wherever
they can be.

| cell | in Arbace (proposed) | corpus | the test's own verdict | oracle tier (records, by hand) |
|---|---|---|---|---|
| **arm64 read** | repr/asm `read` (GNU, Apple, Plan 9 spellings), the assembler's checks of operands (an instruction that does not encode is rejected) | llvm/test MC/AArch64, Disassembler/AArch64's text, gcc's check-function-bodies, musl, Go's testdata, the box | the forms read again equal; each line's stated encoding met; each rejected line rejected with the stated message (`error:` / `ERROR`) | `llvm-mc` 23.1.5's acceptance and encodings; GNU as on the Mac VM |
| **arm64 eval** | a64i: the decoded program run at user level, Linux's calls by name | programs with an entry: hand-written `_start` programs, musl's, gcc's run tests and torture programs as assembly (packs), Go's programs built for linux/arm64 | exit status and stdout (`.out`), torture's exit 0 | native runs on the Mac VM; qemu-aarch64 here |
| **arm64 AOT** | the assembler and the static linker: ELF objects and executables | as read (objects), as eval (executables) | the stated encodings in the object's bytes; the linked executable run on a64i, its verdict | `llvm-mc -filetype=obj` bytes and `llvm-readelf`'s view; the executable run natively on the Mac VM |
| **arm64 print** | repr/asm `print`: canonical (LLVM's spelling), `:full` (the text's own) | every read corpus | `:full` byte for byte; the canonical print read again to the same forms and the same encodings | `llvm-mc`'s canonical text |

Same as the other crops: linux/arm64 for eval and AOT (ELF, AAPCS64, Linux's system calls); read and print take every
dialect, Apple's Mach-O spelling included.

**What differs from a language crop.** The meaning of an instruction is the architecture's, stated by Arm's specification,
not by a compiler; the oracle problem becomes a hardware problem: this host has no arm64 core, so a run's reference is a
recorded native run (the Mac VM), an emulation (QEMU), or the test's own verdict. And unlike LLVM IR, **eval and AOT meet**:
the AOT product is machine code, which the eval stage also runs. §4.2 makes them distinct: eval runs the forms (laid out,
never encoded), AOT runs the bytes (encoded, linked, decoded again), and their agreement is a differential check of the
encoder, the decoder and the linker.

## 2. The syntaxes

### 2.1 GNU as for AArch64 (the reference syntax)

The syntax of binutils' gas and of LLVM's integrated assembler for ELF targets (they agree closely; LLVM's MC is the one the
host can run). Comments `//` and `/* */` (`;` is a statement separator in gas for AArch64, a comment in Apple's); labels
`name:` and numeric labels `1:` with `1b`/`1f`; registers `x0`-`x30`, `w0`-`w30`, `sp`, `wsp`, `xzr`, `wzr`, `v0.4s`,
`q0`/`d0`/`s0`/`h0`/`b0`, `z0.d`, `p0/z` (SVE), `za` tiles (SME); immediates `#imm` (the `#` optional in gas); shifts and
extends (`lsl #12`, `uxtw #2`); addressing `[x0, #16]!`, `[x0], #16`, `[x0, x1, lsl #3]`; relocation specifiers
`:lo12:sym`, `:got:`, `:got_lo12:`, `:tlsdesc:`, `:abs_g0_nc:` ...; aliases (`mov` for `orr`/`movz`/`add`, `cmp` for
`subs`, `lsl` for `ubfm`): the canonical printer chooses the preferred alias, as the Arm ARM's "preferred disassembly"
rules state (§3 P2: `movz w0, #0x1234, lsl #16` prints `mov w0, #305397760`). Directives: gas's generic set (`.text`,
`.section`, `.globl`, `.type`, `.size`, `.p2align`, `.byte`/`.hword`/`.word`/`.xword`/`.quad`, `.ascii`/`.asciz`,
`.macro`/`.irp`/`.rept`/`.if`, `.set`/`.equ`, `.cfi_*`, `.loc`/`.file`) and AArch64's (`.arch`, `.arch_extension`, `.cpu`,
`.inst`, `.tlsdesccall`, `.variant_pcs`, `.req`/`.unreq`). `.S` files go through the C preprocessor first.

### 2.2 Apple's assembler (Mach-O, the Mac)

Apple's `as` is clang's integrated assembler (LLVM MC with a Darwin triple); `llvm-mc -triple arm64-apple-darwin` here
reads it (42 of the 417 base MC files use a Darwin triple, `MC/MachO/AArch64` 14 more). The differences are spellings and
the object format, not instructions: `;` comments; relocation specifiers as suffixes (`adrp x0, _sym@PAGE`, `add x0, x0,
_sym@PAGEOFF`, `@GOTPAGE`, `@GOTPAGEOFF`, `@TLVPPAGE`); symbols with a leading `_`; local labels `L...`/`l...`; Mach-O
sections (`.section __TEXT,__text,regular,pure_instructions`), `.private_extern`, `.subsections_via_symbols`, `.loh`
(linker optimization hints), `.build_version`, no `.type`/`.size`; Apple's ABI (x18 reserved, variadic arguments on the
stack, `svc #0x80` with x16 for system calls). The Mac VM is Linux (ELF), so Apple's syntax and Mach-O are checked here by
llvm-mc's records, and natively only on macOS by hand (a bundle in the manner of `bin/box-mac-bundle`, rarely). Proposed
(ARS4): read and print Apple's spelling over the same forms; AOT writes Mach-O objects only at AR9, no Mach-O linker.

### 2.3 Go's Plan 9 assembler for arm64

Go's own syntax (`doc.go` of obj/arm64, 20 KB): operands in reversed order (`ADD R2, R1, R0` is `add x0, x1, x2`), `R0`-`R30`,
`RSP`, `ZR`, `V0.S4`, `F0`; Go's mnemonics (`MOVD`, `MOVW`, `MOVWU`, `LDP`/`STP` with `(R1, R2)`, `.W`/`.P` for pre/post
index, `BEQ`, `CBZ`, `VADD`, SVE's `Z0.D`, `P0.Z`); addressing `16(R28)`, `(R1)(R2<<3)`; pseudo registers `SB`, `FP`, `SP`,
`PC`; `TEXT`, `DATA`, `GLOBL`, `#include "textflag.h"`, `$imm`, `$sym(SB)`. The assembler is cmd/asm: `cmd/asm/internal/lex`
(a tokenizer with a C-like preprocessor), `asm/parse.go` (arch-neutral, operands to `obj.Addr`), `arch/arm64.go` (the
arm64 rules), then `cmd/internal/obj/arm64`'s `asm7.go` (Prog → machine words) and `obj7.go` (the prologue, the stack
check), writing Go's own object format (goobj), not ELF; the ELF executable is cmd/link's (`cmd/link/internal/arm64` and
`ld`, also in `tamago/cmd/`).

**What can be reused** (all BSD, all forms already, all on the exempt toolchain): the whole Plan 9 path as it is: Arbace's
reader for Plan 9 text can be cmd/asm's lexer and parser themselves (run by goi or compiled into the tool), the encoder
asm7's, and the judge the testdata's comments, as Go's own `TestARM64EndToEnd` does (`cmd/asm/internal/asm/endtoend_test.go`:
each line assembled, its words compared with the comment). From Plan 9 to the crop's forms the bridge is the bytes: Go's
assembler encodes, the decoder (§4.3) reads the words back as A64 forms, and `go tool objdump -gnu`'s pairing (§3 P4)
shows the correspondence line by line. Go's `inst_gen.go` (SVE) is also the encoder's table for GNU syntax's SVE
mnemonics, its rows keyed by Arm's operand templates (`ADDVL #<imm>, <Xn|SP>, <Xd|SP>`).

## 4. The stages

### 4.1 Read (text → assembly forms) and print

- **Reader**: Arbace code (`arbace.repr.asm`, evaluated from the checkout as every crop's reader): a lexer of gas's
  tokens, the statement parser, GNU as's expression language (symbols, `.`, numeric labels, `+ - * / % << >> & | ^ ~ !`,
  relocation specifiers), the macro layer (`.macro`, `.irp`, `.irpc`, `.rept`, `.if*`, `.set`, `.req`), and an operand
  parser by A64's operand classes. `.S` files through repr/c's own preprocessor (`arbace.repr.c.pp`, Arbace's, already
  independent), with the aarch64 predefined macros as data (`__aarch64__`, `__ARM_ARCH`, the feature macros of the chosen
  `-march`).
- **Forms** (spec `doc/asm/SPEC.md` at AR0; principles as LLVM forms': plain Clojure syntax, positional where the text is
  positional, keyword options where it is optional). A sketch, to be settled at AR0:
  `(asm/file :arch :arm64 :syntax :gnu ...)`; a label `(label main)` / `(label 1)`; a directive `(.section ".text" "ax"
  :progbits)`, `(.word 1 2)`; an instruction `(add x0 x1 x2)`, `(add x0 x1 (lsl 12) 4095)`... with operand forms by class:
  registers as symbols (`x0`, `w0`, `sp`, `v0.4s` as `(v 0 :4s)`, `z0.d` as `(z 0 :d)`), memory `(mem x0 16 :pre)`, `(mem x0
  x1 (lsl 3))`, immediates as integers, relocation specifiers `(:lo12 sym)`, expressions as `(+ sym 4)`. The mnemonic is the
  one written; the **architectural instruction** (the Arm ARM's encoding class, the alias resolved) is the assembler's
  view, not the reader's, so `:full` and the canonical print both come from the same forms.
- **Mode `:full`**: comments, blank lines, the spellings of numbers and registers (`#0x10` against `#16`, `X0` against
  `x0`) kept at statement granularity, as repr/c's and repr/llvm's `:full`; printed back byte for byte.
- **The canonical print**: LLVM's InstPrinter's spelling (the preferred alias, lower case, `#imm` in its radix rules), so
  that a canonical print equals llvm-mc's output and the `CHECK:` lines of llvm/test without any tool.
- **Judges of read** (all own verdicts): (1) the forms' `.ae` text read back equal; (2) every line with a stated encoding
  assembles to it (the assembler joins the read judge from AR2: a text the reader takes but that does not encode is not
  read); (3) every line a test states rejected (`error:` check lines, Go's `ERROR "..."`) rejected, with the message
  fragment it states (LLVM's message text is data: the messages are ported as strings, ARS10).

### 4.2 Eval: a64i

- **The machine**: an interpreter of A64 at EL0 in hand-written Go forms (`go/arbace/emu/a64`, as goi's back end and
  `go/arbace/{ci,oi,scm}` are: compiled with the program, light drivers built by TamaGo's go alone), over a frame shared
  with amd64 (§11): guest memory by pages with permissions, the ELF loader (static executables first: `PT_LOAD`, the
  initial stack's argc/argv/envp/auxv with `AT_HWCAP`/`AT_HWCAP2` stating what a64i implements, `AT_RANDOM`, the vDSO absent),
  and **Linux's system calls by name** on `go/arbace/crt`'s implementations: arm64 uses the generic table
  (`asm-generic/unistd.h`: `svc #0`, the number in x8, arguments x0-x5, the result in x0), so the frame maps arm64's numbers
  and struct layouts (`struct stat` is the generic one on arm64, not x86-64's; `sigcontext` and the signal frame are
  arm64's) onto names crt already serves.
- **State**: x0-x30, sp, pc, NZCV, v0-v31 (128 bits), FPCR/FPSR, TPIDR_EL0; the system registers EL0 may read (CNTVCT_EL0,
  CNTFRQ_EL0, MIDR via the ID registers' trap emulation, DCZID_EL0, CTR_EL0); exclusive monitors for `ldxr`/`stxr`; LSE
  atomics; PAuth and BTI as NOPs where the hint space allows and a class otherwise; SVE/SME refused in a class until AR11.
- **The semantics**: per encoding class, from the Arm ARM's descriptions (written by Arbace; §6 on what may be translated
  mechanically). Floating point: IEEE 754 with FPCR's rounding modes and flush-to-zero, NaN propagation as the Arm ARM's
  `FPProcessNaNs` (Go's floats give the arithmetic; the NaN payload rules and FPSR's cumulative flags need their own
  code: a class `:fp-flags` until done).
- **Threads and signals**: `clone` as a guest thread on a deterministic scheduler of the frame (one host goroutine running at
  a time, switched at system calls and at an instruction budget, so that runs are reproducible); futexes over guest
  memory; signal delivery with arm64's `rt_sigframe`; `tgkill` to self. P5 shows a Go program needs all of it.
- **Two inputs, one machine**: eval runs **the forms** (the assembler's layout gives every label and datum an address, the
  instructions are executed from their forms, never encoded); AOT's executables run **the bytes** through the decoder. A
  program that reads its own code as data is the forms path's class (`:code-as-data`).
- **Where real arm64 runs it natively**: on the Mac VM the same Arbace executable (stage 0 is built there for arm64 already:
  journal, queue 155) runs a64i, and the program itself runs natively: the native run is the oracle (§8), recorded there.
  a64i's own `svc` path could later run on the box's arm64 guest (TamaGo on Hypervisor.framework), out of this plan.

### 4.3 AOT: the assembler, the objects and the linker

- **Encoder**: forms → 32-bit words, by tables (ARS5), with the relocations and fixups (`R_AARCH64_ADR_PREL_PG_HI21`,
  `ADD_ABS_LO12_NC`, `CALL26`, `JUMP26`, `CONDBR19`, `LDST*_ABS_LO12_NC`, `ADR_GOT_PAGE`, `TLSDESC_*`, `ABS64`, `PREL32`
  ...), branch range checks, literal pools (`ldr x0, =imm`), `.inst`, alignment padding with `nop`.
- **Decoder**: words → forms, from the same tables (an encode-decode-encode identity is a self-check over every table row);
  arm64asm (§2.3) is the decoder to port first, its GNU printer a second opinion on the canonical print.
- **ELF objects**: ELF64 little-endian `ET_REL`, `.text`/`.data`/`.bss`/`.rodata`, `.symtab`/`.strtab`, `.rela.*`, `.eh_frame`
  from `.cfi_*` (shared with amd64), `.note.GNU-stack`, BTI/PAC properties (`.note.gnu.property`). Judged by the test's
  stated words (the object's section bytes) and by llvm/test's `llvm-readobj`/`llvm-objdump` check lines where Arbace prints
  the same views (a small `readelf -r`/`-s` of its own; ARS9).
- **The static linker**: `ET_REL` → `ET_EXEC` (static, no PIE first; `_start` the entry), the relocations applied, GOT
  entries made for `:got:` references, TLS (local-exec, initial-exec relaxed), `.init_array`. Shared with amd64 except the
  relocation table.
- **What AOT does not mean here**: translating A64 to Go forms for a native amd64 program (cf2g's way) is a possible later
  milestone (AR13, optional), a faster eval, not this cell.

### 4.4 The judge

- **Own verdicts** (ruled independent, 2026-11-07): llvm/test's stated encodings, canonical spellings and rejection messages,
  read from its `CHECK`/`CHECK-ENCODING`/`CHECK-ERROR` lines by a FileCheck subset (the LLVM row's own-verdict reader of
  `ee.*` tests: lines in order, blanks collapsed; the prefixes the RUN lines give; a file whose directives the subset does
  not take has no own verdict, its record judges); Go's testdata comments (as `endtoend_test.go`); Disassembler's `.txt`
  (each word's stated text); gcc's check-function-bodies (each body's regular expressions matched by the canonical print of
  the same function: an own verdict of the printer and the reader both); a run program's exit status and output
  (`$GOROOT/test`'s `.out`, torture's exit 0, musl-linked tests' `abort()`).
- **Records** (0.5): llvm-mc's acceptance, encodings and canonical text for files the subset cannot judge; native runs on the
  Mac VM for programs without an own verdict.
- **Classes**: `test/asm/arm64/divergences{,-read,-aot,-print}.edn`, goi's format. Expected kinds: `:sve`, `:sme`
  (deferred), `:system` (EL1+ instructions: read and AOT only, never run), `:apple-object` (Mach-O at AR9), `:fp-flags`,
  `:threads`, `:speed`, `:code-as-data`, `:message` (a rejection with another wording), `:feature` (an instruction of an
  extension the hardware oracle lacks).

## 7. Independence

`bin/crops-score`'s rule per stage: 1 with no host toolchain at check time and no record of one consumed; 0.5 with a record
made by a host toolchain or the toolchain only at the oracle tier; 0 with a live toolchain at check time. TamaGo's go and
its sources (`tamago/cmd/`) are not counted (CROPS-SCORE.md).

| stage | what runs at check time | inputs | score (planned) |
|---|---|---|---|
| read | repr/asm on stage 0; `.S` through repr/c's preprocessor | llvm/test, gcc's tests, musl, Go's testdata, the box: all source text, no toolchain output | **1** |
| eval | a64i in the tools' executable or its light driver | hand-written programs, musl's `.s`, **Go programs built by TamaGo's go** (1); gcc's and clang's `-S` output as packs (0.5) | **0.5 to 1**, by the share of cases from packs (the case-weighted mean, 2026-11-07) |
| AOT | the assembler and linker; Go's assembler (forms, exempt) for Plan 9 | as read and eval | **1** (0.5 for the packs' cases) |
| print | repr/asm's printer | the read corpora | **1** |
| judge | the own verdicts (§4.4) | llvm/test's check lines, Go's comments, `.out` files, exit statuses | **1** for those; **0.5** for files judged by llvm-mc's record or a native run's record |

(`:phase :oracle`, `bin/gate --oracle`), a step whose host is absent being `absent`. The host ids to add (GT9's `:host-ids`):

## 8. How records get made

This host has no arm64 core, so a run's reference comes from one of four places, by cost:

1. **This host, the oracle tier** (`bin/gate --oracle`, by hand at a tag): `llvm-mc -triple aarch64-linux-gnu
   -show-encoding`/`-filetype=obj`/`--disassemble` over the read corpora → `test/asm/arm64/ref-llvm-mc23.edn` (acceptance,
   words, the first error line, the canonical text's digest); `llvm-objdump -dr`/`llvm-readelf -rs` of Arbace's objects;
   `clang --target=aarch64-linux-musl -S -O0|-O2` with musl's aarch64 headers (a sysroot for aarch64 assembled as
   `bin/lib/repr-c/sysroot.bash` does for x86-64) over gcc's torture programs, gcc.target/aarch64's run tests and musl's C
   → the **packs** `asm-arm64-clang-tx`, `asm-arm64-clang-musl` (deterministic tar.xz, a manifest of input digest → member
   digest, `bin/oracle-records`, doc/ORACLE-RECORDS-SURVEY.md); `qemu-aarch64` runs of Arbace's executables (if ARS12
   allows: an emulation's verdict, labelled so).
2. **The Mac VM** (the queue repo, a task per recording, light): native `gcc -S` over the same inputs (the pack
   `asm-arm64-gcc-tx`, GNU as's acceptance of Arbace's canonical print, `objdump -d` of Arbace's objects), and **native runs**
   of Arbace's AOT executables and of the corpus programs built there (`ref-native-m2.edn`: status, stdout's digest,
   `/proc/cpuinfo`'s features). The records come back on a `mac/NNN-...` branch and are merged as data. The M2 has no SVE,
   SME or MTE (to verify on the VM): those tests are `:feature` there.
3. **The emulated aarch64 VM** (`bin/box-arm64-vm`): QEMU system emulation with `-cpu max` (SVE, SME, MTE present), so
   the only place here where SVE code runs on something that is not a64i; slow (the box starts in 13 s against 0.3 s
   natively), its Alpine apks fetched by the VM itself (§5.3).
4. **macOS** (Apple's `as`, Mach-O, Apple's ABI): by hand through a bundle, only for AR9's spellings and objects.

Recording runs are never `--record`ed by the gate (C's rule since 2026-11-02): by hand, at night, their commands in the
milestone's "night's runs" table.

## 11. Shared with amd64

Proposals for the merge of this survey with doc/asm/AMD64-SURVEY.md into one plan. Each is a shared piece, what stays
per arch, and the recommendation.

- **SH1 One crop directory, two rows.** (a) `doc/asm/`, `arbace/repr/asm/`, `arbace/asm/`, `go/arbace/emu/`, `test/asm/`
  shared, with `arm64/` and `amd64/` below each; two REAP rows `:asm-arm64` and `:asm-amd64` and two crops in
  `crops.edn` (completeness and independence differ by arch: amd64's eval can be checked natively here, arm64's not);
  (b) one row `:asm` with the arches as parts; (c) two independent crops sharing nothing. *Recommended: (a)*, as LLVM's
  row and C++'s share the lowering but keep their rows.
- **SH2 The forms' shell.** Shared: `(asm/file :arch :syntax ...)`, labels (named, numeric, local), sections and the GNU
  directives (data, alignment, symbols, `.type`/`.size`, `.cfi_*`, `.loc`, `.set`/`.equ`), expressions and relocation
  specifiers as forms, comments and layout in `:full`, the macro layer (`.macro`, `.irp`, `.rept`, `.if*`). Per arch: the
  instruction and operand forms, the aliases, the canonical printer. AT&T and Intel syntaxes (amd64's) and GNU/Apple/Plan 9
  (arm64's) are spellings over the shared shell. *Recommended*: one spec, `doc/asm/SPEC.md`, its §1-§4 shared.
- **SH3 `.S` through repr/c's preprocessor.** Shared, with the predefined macros per arch as data (`c/target/`'s way).
- **SH4 The ELF writer, reader and static linker.** Shared: ELF64 LE, sections, symbols, string tables, `.rela`,
  `.eh_frame` from CFI, notes, `ET_REL` and static `ET_EXEC`, GOT and TLS models, a `readelf`-like printer for judging
  (llvm/test's `llvm-readobj` checks). Per arch: the relocation types and their computations, PLT/veneer stubs, the
  e_machine. `debug/elf` (forms in `tamago/goroot`) as the reader's second opinion. *Recommended*: written once at the
  first arch's AOT milestone, the second arch adding a relocation table.
- **SH5 The emulator's frame.** Shared (`go/arbace/emu`): guest memory (pages, permissions, `mmap`/`brk`/`mprotect`), the
  ELF loader and initial stack (auxv), **Linux's system calls by name** over `go/arbace/crt` (each arch a table of numbers
  and struct layouts: x86-64's own, arm64's the generic), signals (the frame's delivery logic; the frame layout per arch),
  `clone` threads on a deterministic scheduler, futexes, the instruction budget and the `:speed` class, a trace format for
  differential runs (registers after each instruction, comparable with a recorded trace). Per arch: decode, execute,
  registers, flags, the FP and vector state. *Recommended*: the frame at the first eval milestone (whichever arch is first),
  its system call table split by arch from day one.
- **SH6 The judge.** Shared: llvm/test's own-verdict reader (a FileCheck subset, the LLVM row's, extended to `CHECK-ENCODING`,
  `CHECK-ERROR`, `CHECK-INST` prefixes), Go's testdata reader (`// hex` and `ERROR`), the run verdicts, the negative controls
  (a case's run judged against another case's verdict must fail), the classes files, the packs' manifests and the oracle
  host ids (`:llvm`, `:arm64` for hardware records, amd64's native runs here). *Recommended*: one `arbace.asm.check`.
- **SH7 Table-driven encode/decode.** Shared: the harness (tables as data, generated and `--check`ed; encode → decode →
  encode over every row; the decoder's output printed canonically against the test's stated text). Per arch: the tables'
  source (arm64: Go's optab and instgen output, arm64asm, Arm's specification; amd64: its survey's choice, e.g. x86asm's
  tables in the same `cmd/vendor`). *Recommended*: one generator interface, one check verb.
- **SH8 Plan 9 is one reader.** Go's cmd/asm is arch-neutral (`asm/parse.go`) with arch plugins (`arch/arm64.go`,
  `arch/amd64` in `arch.go`), and `cmd/internal/obj/{arm64,x86}` are both in `tamago/cmd/`. *Recommended*: one Plan 9
  path for both arches, judged by Go's testdata (`amd64enc.s` and friends for amd64).
- **SH9 The corpora's tools.** Shared: llvm-project's extraction (the LLVM row's `bin/llvm-corpus`), gcc's (C's), Go's
  testdata in place, the packs' recording scripts (clang `-S` for both arches over the same C inputs: one pack per arch).
- **SH10 Names.** `bin/repr-asm --arch A`; the emulator per arch (`bin/a64i`, and amd64's choice, e.g. `bin/x64i`) or one
  `bin/asmi --arch A`. *Recommended*: one `bin/repr-asm`, the emulators per arch's name over one driver library (the
  crops' `-i` pattern, ARS14).

What should not be shared: the canonical printers (each arch's reference spelling is its own assembler's), the
instruction semantics, the oracle routes (amd64 runs natively here; arm64 only on the Mac VM).

## 15. Risks

- **No arm64 core on this host**: every run reference is a record from elsewhere or a test's own verdict. If the Mac VM is
  busy, eval's non-own-verdict cases stay at 0.5 and their records age. The own verdicts (Go's `.out`, torture's exit 0) carry
  the cell; the records are a second opinion.
- **SVE and SME are most of llvm/test's AArch64 files** (1,943 of 2,360) and have no hardware oracle here or on the M2; AR11
  is optional and the base row's completeness counts them as deferred until then (a large deferred share: ARS1's row would
  read low on completeness without by design if they are counted; to decide with AR0's counts whether the extensions' files
  belong to the row's corpus or to AR11's).
- **The canonical spelling is LLVM's**, which gas and arm64asm differ from in details (P2, P4); the print cell's own verdict
  is LLVM's `CHECK:` text, so a gas-flavoured print would need its own judge.
- **Go programs need the hard parts of Linux at once** (P5: threads, futexes, signals): AR7 is where a64i's frame meets
  reality; `GODEBUG=asyncpreemptoff=1` and `GOMAXPROCS=1` reduce it at first, a class says so.
- **Speed**: an interpreter in Go forms of a machine language; Go's runtime start is many instructions. The `:speed` class
  and the budget's share decide how much of goi's corpus runs nightly; AR13 is the remedy if needed.
- **Licences**: Arm's specification packages differ; nothing is generated from one before its licence text is read and
  entered. GPL tools (binutils, QEMU) are run at the oracle tier only, never read for porting.
- **Version churn**: llvm/test's MC files move with LLVM's releases (23.1.4 → 23.1.5 already); the extensions' directories
  grow every release. Pinned with the LLVM row; a bump re-records `ref-llvm-mc23.edn` and recounts.
